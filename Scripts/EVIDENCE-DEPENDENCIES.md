# Evidence dependency inventories

[`evidence-dependencies.json`](evidence-dependencies.json) is the maintained source inventory for the global solar, local solar, observer event, planetary event, transit, lunar eclipse, Moon event, Moon full-integration, Pluto observer, Pluto native, Galilean residual, and Galilean runtime artifacts. It lists exact repository paths rather than discovering every Swift file below `Engine`.

Each shared group declares its required owners, and each owner declares its groups. The loader requires those declarations to agree, requires the complete owner set, rejects duplicate or malformed paths, and requires every expanded path to be a file. A missing or renamed dependency therefore stops recording and checking instead of silently reducing coverage.

The lunar eclipse, Moon event, Moon full-integration, Pluto native, and Galilean runtime recorders previously discovered every Engine Swift file. Their maintained inventories conservatively retain all 251 Engine files present when they were migrated; these are broad snapshots rather than claims of minimal runtime dependency sets. An edit to any listed Engine file therefore invalidates those artifacts. A newly added Engine file does not enter an owner automatically and must be assigned explicitly when it can affect that result.

When a result starts using another file, add its exact path to an existing group or add a new group, then add every affected owner to both the group and owner declarations. Keep a dependency when its influence is uncertain. Do not add unrelated files to make a check pass.

Run `python3 Scripts/test_evidence_dependencies.py` after editing the inventory. Its controls cover direct and transitive edits, unrelated Engine additions, inventory additions, physical deletion or rename, malformed and duplicate entries, and missing required ownership coverage.

An ownership-only migration can rebind archived measurements only when `verify_retained_inputs` proves that every retained result dependency still has its preceding digest and `verify_rebound_document` proves that every non-binding evidence field is identical. The check compares the union of the preceding and current inventories, so removing an owner or path fails closed. A newly declared dependency requires a fresh measurement because the existing recorder metadata does not attest which source bytes produced imported measurement files. An inventory edit or a matching file at a later revision cannot approve an archived measurement. The shared inventory files, the executing recorder, and Python replay tests are replay machinery; changes to runtime sources, generated inputs, Swift capture tests, fixtures, or references require a fresh capture.

Use the recorder command for the affected artifact and then its `--check` command. Planetary event evidence uses `--rebind` for a guarded ownership-only migration, Pluto observer evidence uses `--rebind-native`, and Galilean residual evidence uses `--capture` when its Swift measurement owner or result inputs change. The lunar eclipse, Moon event, Moon full-integration, Pluto native, and Galilean runtime migrations require fresh captures because their archived evidence did not bind every now-declared input. The Galilean runtime recorder enumerates the source tree only to report `astronomyKitSourcesBytes`; its dependency binding comes from the maintained inventory. Never edit a stored digest by hand.
